# 数据、方法与主要结果

本文是项目技术结果的详细说明，适合直接作为实验教学案例、教学成果申报附件或项目答辩的技术部分使用。数字均来自仓库内数据文件和竞赛阶段实验记录；凡是代码尚未严格实现或无法由现有记录复核的内容，均单独标注。

## 一、数据说明

项目保留了两份交易型数据集，分别用于大规模交易建模和小规模教学/原型实验。

### 1. `transactions.csv`

| 项目 | 内容 |
| --- | --- |
| 记录数 | 1,048,575 条 |
| 字段数 | 8 个 |
| 交易标识 | `TX_ID`，1,048,575 个唯一值 |
| 参与方 | `SENDER_ACCOUNT_ID` 9,999 个，`RECEIVER_ACCOUNT_ID` 9,914 个 |
| 交易类型 | `TX_TYPE` 全部为 `TRANSFER` |
| 金额 | `TX_AMOUNT`，最小 0，最大 21,500,000，中位数 156.72，均值约 29,812.85 |
| 时间 | `TIMESTAMP` 为离散数值编码，取值范围 0–158 |
| 告警 | `ALERT_ID` 中 1,047,246 条为 `-1`，其余为告警关联记录 |
| 标签 | `IS_FRAUD`：1,047,246 条 `FALSE`，1,329 条 `TRUE` |
| 标签比例 | 欺诈标签约 0.1268%，呈现极度类别不平衡 |

该数据集的价值在于规模较大、账户关系较丰富、正负样本高度不平衡，适合引导学生讨论大样本训练、异常检测、少数类识别和评价指标选择。金额均值显著高于中位数，也可以作为偏态分布和极端值处理的教学切入点。

### 2. `transactions_micro.csv`

| 项目 | 内容 |
| --- | --- |
| 记录数 | 10,333 条 |
| 字段数 | 8 个 |
| 交易标识 | `tran_id`，全部唯一 |
| 参与方 | `orig_acct` 98 个，`bene_acct` 100 个 |
| 交易类型 | `tx_type` 有 4 类：1、2、3、4 |
| 金额 | `base_amt`，范围 94.09–1,086.76，中位数 557.73，均值约 554.81 |
| 时间 | `tran_timestamp`，10,332 条记录可解析，覆盖 2010-01-01 至 2011-12-21；另有 1 条记录将金额 `671.66` 错置在时间字段 |
| 告警 | `alert_id` 中 10,282 条为 `-1`，其余为 0、1、2 三类告警 |
| 标签 | `is_sar`：10,282 条 `FALSE`，51 条 `TRUE` |
| 标签比例 | 可疑活动标签约 0.4936%，同样存在类别不平衡 |

该数据集体量较小、字段更适合课堂快速运行，包含交易类型和时间戳，适合作为数据字典、清洗、特征编码、训练/测试划分和实验迭代的入门数据。时间字段中的 1 条错位记录可作为数据质量修复练习：不能直接将其强制转换为日期，应回查原始记录并决定删除、修复或标记。

### 3. 数据教学中的关键发现

两份数据的字段命名、标签命名和标签位置不同：大数据集以 `IS_FRAUD` 作为最后一列，小数据集以 `is_sar` 作为倒数第二列、`alert_id` 为最后一列。因此，数据读取后不能仅依赖“最后一列就是标签”的假设，必须先做字段审计。这是本项目特别适合实验教学的地方：学生不仅学习模型，也学习数据契约、字段语义和可复现性。

## 二、数据处理方法

原始实验脚本采用以下处理链路：

1. **读取**：使用 Pandas 读取 CSV；
2. **去标识**：删除交易 ID、交易类型或告警 ID 等字段；
3. **缺失值处理**：使用前向填充处理缺失值；
4. **切分**：使用 `train_test_split` 按 80%/20% 划分训练集和测试集，随机种子为 42；
5. **建模**：使用 XGBoost 的树模型训练二分类/二类别任务；
6. **评价**：输出准确率和 ROC AUC，并绘制学习曲线与特征重要性。

这里既包含可复用的工程步骤，也保留了值得学生修正的实验问题：前向填充是否适用于无序交易数据？交易类型是否应删除而不是编码？随机切分是否会造成时间信息泄漏？类别极不平衡时，准确率是否会掩盖少数类识别失败？这些问题可以转化为实验报告中的“方法批判与改进”部分。

## 三、模型方法

### 1. XGBoost

项目选择 XGBoost，是因为交易风险通常具有非线性、特征交互和异常值并存的特点。梯度提升树可以通过多棵弱学习器逐步拟合残差，并通过树深、学习率、子采样、列采样和正则化等参数控制复杂度。

原型中使用的代表性参数包括：

| 参数 | 原型设置 | 教学含义 |
| --- | ---: | --- |
| `booster` | `gbtree` | 使用树模型处理非线性关系 |
| `max_depth` | 3 | 控制单棵树复杂度 |
| `eta` / `learning_rate` | 0.1 或 0.2 | 控制每轮更新步长 |
| `gamma` | 0.1 | 控制节点分裂所需的最小收益 |
| `subsample` | 0.7 | 对样本进行子采样，降低过拟合风险 |
| `colsample_bytree` | 0.7 | 对特征进行列采样 |
| `min_child_weight` | 3 | 控制叶节点继续分裂的条件 |
| 训练轮数 | 500 | 通过多轮提升拟合训练数据 |

### 2. 参数搜索与解释

`grid_searcher.py` 使用 `GridSearchCV` 对 `n_estimators` 和 `max_depth` 进行网格搜索，并采用 5 折交叉验证、`accuracy` 作为评分。脚本还输出特征重要性图，帮助学生从“模型给出结果”进一步走向“解释模型为什么给出结果”。

针对本项目的数据不平衡特征，教学中应要求学生扩展评价：混淆矩阵、Precision、Recall、F1、PR-AUC、不同阈值下的告警数量和误报成本。ROC AUC 也应基于概率输出而不是硬分类标签计算，避免评价信息损失。

## 四、联邦学习方法

FedBoost 的设计目标是让多个 NFT 平台在不集中原始交易数据的前提下共同提升识别能力。一次联邦训练可以拆为：

1. 协调方初始化模型并向参与方下发模型版本；
2. 各平台在本地数据上训练，原始交易记录留在本地；
3. 各平台上传模型更新、参数或经过保护的统计量；
4. 协调方进行聚合，形成联合模型；
5. 将新模型下发，进入下一轮训练；
6. 在统一验证集或各平台本地验证集上比较效果。

`FedBoost.py` 使用 PySyft 虚拟工作节点展示多方训练概念，但当前代码属于竞赛阶段概念验证：示例使用随机生成数据，模型聚合逻辑是简化版本，且依赖旧版 PySyft/Torch 接口。因此，本项目对联邦学习的教学价值主要体现在流程理解、隐私边界分析和系统架构设计，不应把该脚本表述为已完成的生产级安全聚合系统。

## 五、主要结果

### 1. 原始实验记录

仓库中的 `algorithms/fedboost/results.txt` 记录了以下结果：

| 数据集记录名 | 原始记录的准确率 |
| --- | ---: |
| IBM | 0.9998617170922443 |
| micro | 1.0000000000000000 |

这两项结果说明竞赛阶段原型能够完成训练、预测和结果记录，适合作为教学中的“结果复现入口”。但由于原始记录没有同时保存固定的数据划分、混淆矩阵、Recall、F1、概率预测、完整参数搜索日志和运行环境，现阶段不能据此宣称模型具有经过严格验证的生产性能。

### 2. 结果解读

- IBM 数据集标签正例仅约 0.1268%，如果模型全部预测为正常，也可能获得很高的准确率，因此必须结合少数类 Recall、Precision、F1 和 PR-AUC 判断真正的反洗钱识别能力；
- micro 数据集正例约 0.4936%，同样存在类别不平衡，`1.0` 的准确率需要结合测试集样本数量和预测分布复核；
- 现有代码把“实验能运行”和“结果可信”区分得不够充分，这为教学提供了改进任务：固定随机种子、明确标签字段、分层切分、保留概率输出、记录混淆矩阵并进行重复实验；
- 对交易数据更合理的后续设计是按时间切分训练集和测试集，并避免同一账户或同一交易链条同时泄漏到训练集和测试集。

### 3. 平台化结果

算法结果通过平台承接为三个层级的业务输出：

1. **交易层**：风险列表和告警记录，支持筛选和后台处理；
2. **用户层**：可疑用户查询、详情、维护和导出；
3. **关系层**：通过交易链条页面展示可疑交易关联关系，辅助人工溯源。

平台 SQL 进一步把 `user`、`nft`、`activity`、`trades_info`、`user_game_relationship` 和 `game_info` 等业务对象结构化，形成从交易记录到用户、NFT 和平台治理的连接。也就是说，项目的主要成果不是单一准确率，而是完成了“数据样例—模型原型—联邦方案—业务数据库—风险管理页面”的贯通。

## 六、可用于教学评价的结果指标

建议教师要求学生提交下表，而不是只提交一项准确率：

| 结果类别 | 必交指标/材料 | 对应能力 |
| --- | --- | --- |
| 数据质量 | 样本数、字段数、缺失值、唯一值、标签比例、异常值 | 数据审计 |
| 模型效果 | Accuracy、Precision、Recall、F1、ROC AUC、PR-AUC、混淆矩阵 | 科学评价 |
| 稳定性 | 不同随机种子、不同切分方式、交叉验证均值与标准差 | 可复现与泛化 |
| 模型解释 | 特征重要性、错误样本分析、阈值变化 | 可解释建模 |
| 系统实现 | API、数据库表、页面、权限和操作日志 | 工程交付 |
| 安全治理 | 数据授权、隐私边界、最小权限、审计和人工复核流程 | 负责任创新 |

## 七、结论与边界

项目已经完成竞赛阶段的原型闭环：有数据、有算法、有联邦学习方案、有数据库和平台页面，也有技术文档、商业计划书和展示材料。其最适合作为“复杂问题综合实验”而不是“生产反洗钱系统”来呈现。教学申报时建议将成果表述为：**通过真实业务约束组织多课程知识，培养学生从数据审计、模型实验到平台交付的综合实践能力，并在隐私、安全和结果可信性方面形成批判性技术意识。**
