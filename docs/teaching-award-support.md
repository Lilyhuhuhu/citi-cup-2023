# 实验教学成果支撑材料

## 一、成果名称

**面向真实复杂问题的“数据—算法—系统—治理”贯通式实验教学：基于联邦学习的 NFT 可疑交易监测与平台安全评估项目**

本项目以 NFT 交易反洗钱这一跨学科、强实践、重安全的真实问题为载体，将数据分析、机器学习、隐私计算、数据库、软件工程、Web 开发、区块链和创新创业教育组织为一条连续的实验教学链路。学生不是只提交一个模型或一组页面，而是经历“发现问题—分析需求—处理数据—训练模型—讨论隐私—开发平台—评价安全—展示成果”的完整工程实践。

## 二、教学改革要解决的问题

传统实验容易出现三个断点：

1. **知识断点**：Python、数据库、机器学习和 Web 开发分别授课，学生会做局部练习，却难以理解知识如何共同解决复杂问题；
2. **任务断点**：实验以验证语法和复现算法为主，缺少需求分析、数据质量、模型解释、接口设计和系统交付等真实约束；
3. **价值断点**：学生往往只关注准确率，忽略隐私保护、权限控制、审计追踪、数据授权和模型局限，难以形成负责任的技术观。

本项目以一个可持续扩展的业务场景串联上述环节，用平台化成果承接算法结果，使学生能够看到知识从课堂概念转化为工程能力和社会责任。

## 三、教学目标

### 1. 知识目标

- 理解交易型数据的字段、标签、缺失值、类别不平衡和时间关联等基本特征；
- 掌握 XGBoost 的基本原理、关键参数、训练流程和准确率/AUC 等评价方法；
- 理解联邦学习“数据留在本地、协作训练模型”的基本思想，辨析联邦学习不等于天然安全；
- 掌握关系数据库建模、REST 接口、前后端分离和权限控制在业务系统中的作用；
- 了解 NFT 交易链条、平台治理和反洗钱风险之间的关系。

### 2. 能力目标

- 能够从业务问题抽象出数据字段、标签、实体关系和评价指标；
- 能够独立完成数据清洗、特征处理、模型训练、参数搜索、可视化和结果解释；
- 能够将算法输出设计为可查询、可追踪、可审计的平台功能；
- 能够阅读和修改跨语言工程代码，完成 Python、Java、Vue、SQL 之间的协同；
- 能够通过实验记录、技术文档、演示和答辩清晰表达技术方案与边界。

### 3. 素养目标

- 建立隐私保护、最小权限、数据授权和安全审计意识；
- 形成以证据和实验结果支撑结论的科研与工程习惯；
- 理解高准确率不等于高可靠性，能够主动识别数据泄漏、样本偏差和过拟合风险；
- 培养团队协作、项目管理、产品思维和面向社会问题的责任意识。

## 四、教学内容组织

项目按照能力递进组织为八个实验单元，每个单元既有可独立评价的产出，又为下一单元提供输入。

| 单元 | 核心问题 | 主要知识点 | 学生产出 |
| --- | --- | --- | --- |
| 1. 场景与需求 | 什么是 NFT 交易风险，谁需要系统 | 需求分析、用户画像、风险场景 | 问题定义、业务流程图、指标初稿 |
| 2. 数据认知 | 数据能否直接用于建模 | CSV、字段分析、缺失值、标签检查 | 数据字典、清洗记录、探索性分析 |
| 3. 模型基线 | 如何识别可疑交易 | 分类建模、训练/测试划分、准确率与 AUC | 基线模型与实验报告 |
| 4. XGBoost 优化 | 如何提升模型效果并解释结果 | 梯度提升树、参数搜索、特征重要性、学习曲线 | 参数对比、可视化和结论 |
| 5. 联邦协作 | 数据不能集中时如何共同训练 | 联邦学习、参与方、聚合、隐私边界 | 联邦流程图、原型代码、风险分析 |
| 6. 数据库与接口 | 模型结果如何进入业务系统 | 实体关系、SQL、REST、分页和权限 | 表结构、接口清单、后端模块 |
| 7. 平台实现 | 如何让业务人员使用结果 | Vue、交互设计、风险列表、链条追踪 | 风险平台页面和操作演示 |
| 8. 综合评价 | 系统是否安全、可用、可解释 | 平台安全评估、审计、伦理、项目表达 | 安全评估报告、答辩材料、反思报告 |

## 五、实验教学实施方式

### 1. 项目驱动

教师不以零散 API 演示作为主线，而是先给出“多个 NFT 平台希望联合识别可疑交易，但不能直接交换原始数据”的任务情境。学生围绕任务自主拆解角色、数据、模型、接口和平台功能，教师在关键节点提供最小必要的知识支架。

### 2. 分层任务

- **基础层**：完成数据读取、清洗、训练和指标计算；
- **提高层**：完成参数搜索、特征解释、联邦训练流程设计和数据库接口；
- **拓展层**：完成安全聚合、差分隐私、规则引擎、时间切分、模型监控或新的前端可视化设计。

分层设计既保证基础薄弱学生能够完成闭环，也为能力较强学生保留研究和创新空间。

### 3. 教师指导与学生协作

教学过程采用“教师示范关键方法—学生小组分工实现—阶段评审—同伴互评—教师反馈—迭代提交”的方式。建议小组设置业务分析、数据建模、算法、后端、前端和安全评估等角色，并要求每名学生提交个人贡献记录，避免只评价最终演示效果。

### 4. 过程性评价

评价不以一次性准确率或页面截图为唯一依据，而是综合考查问题理解、数据处理、算法实验、工程实现、安全意识、文档表达和团队贡献。建议评价构成为：过程实验 40%，阶段评审 20%，综合平台与技术报告 30%，答辩和反思 10%；教师可根据课程性质调整权重。

## 八、教学创新与特色

### 1. 从“算法实验”升级为“完整工程实验”

学生不止训练模型，而是将模型结果继续转化为用户筛查、交易链条追踪和平台安全评估，完成从数据到系统的闭环，强化知识迁移和工程交付能力。

### 2. 将隐私计算从概念变成约束条件

“平台不能共享原始数据”不是课后讨论题，而是贯穿数据、算法和系统设计的真实约束。学生必须在模型效果、数据可用性、隐私风险和部署成本之间进行权衡。

### 3. 将安全与伦理嵌入技术评价

平台同时考察身份认证、双因素认证、最小权限、交易透明性、链条追踪和审计等指标，引导学生认识到一个识别率很高的模型，如果缺少权限、解释和治理，同样不能直接用于真实业务。

### 4. 用可运行平台承接学习证据

通过 API、数据库和前端页面，学生的学习成果从“代码文件”变为可操作、可演示、可评审的系统，便于教师进行过程观察、阶段验收和成果归档。

## 九、教学成效评价

基于项目代码、数据样例、实验脚本、数据库设计、前后端平台、技术文档、商业计划书和展示材料，可以对本项目形成的实验教学成效作出以下评价。

### 1. 学生实现了从单点知识到综合应用的迁移

项目没有停留在“调用一个算法库并输出准确率”，而是形成了从业务问题到技术系统的完整证据链。学生需要先理解 NFT 交易和反洗钱场景，再完成数据字段审计、标签识别、缺失值处理、模型训练、结果评价、联邦流程设计、数据库建模、接口开发和前端展示。由此，Python、机器学习、数据库、软件工程、Web 开发、信息安全和区块链等知识不再以孤立章节出现，而是在同一任务中相互调用，体现出较强的知识迁移和综合实践特征。

### 2. 学生形成了较完整的数据分析能力

项目提供了两种规模和结构不同的交易数据：一份包含 1,048,575 条记录，另一份包含 10,333 条记录。数据中既有账户关系、交易金额、时间、交易类型和告警编号，也存在标签命名不一致、类别极度不平衡和时间字段错位等真实数据问题。围绕这些数据开展实验，能够促使学生从“数据能不能读入”提升到“字段是否可信、标签是否正确、样本是否平衡、处理方式是否会影响结论”的数据意识。

从教学结果看，项目把数据清洗从模型训练的附属步骤转化为独立的学习任务，使学生能够认识到数据质量、字段语义和样本分布是影响模型可信度的前置条件。这一过程尤其适合培养学生的数据审计能力和实证意识。

### 3. 学生掌握了从基线模型到模型解释的实验方法

项目以 XGBoost 为核心完成交易风险识别，实验代码包含训练/测试集划分、参数设置、网格搜索、交叉验证、准确率和 ROC AUC 计算、学习曲线及特征重要性可视化。学生由此能够经历“建立基线—调整参数—比较结果—解释模型”的基本机器学习实验范式，而不是只记忆算法名称。

项目原始记录显示：IBM 数据集准确率为 `0.9998617170922443`，micro 数据集准确率为 `1.0`。教学上更重要的成效在于，项目同时暴露了高准确率背后的类别不平衡问题：IBM 数据集正例约占 `0.1268%`，micro 数据集正例约占 `0.4936%`。因此，学生必须进一步讨论 Recall、Precision、F1、PR-AUC、混淆矩阵和误报成本，理解“指标很高”与“模型真正有用”之间的区别。这使模型评价由结果崇拜转向证据分析和批判性判断。

### 4. 学生建立了隐私计算和安全治理意识

项目将“多个平台不能直接共享原始交易数据”设置为技术约束，引导学生理解联邦学习的参与方、本地训练、模型更新、聚合和下发流程。与普通的集中式机器学习实验相比，学生不仅要回答“模型效果如何”，还要回答“数据能否出域、交换什么信息、参数是否可能泄露、协调方是否可信、如何进行人工复核”等问题。

项目材料还将安全评估扩展到用户认证、双因素认证、令牌铸造、NFT 上市、交易透明性、最小权限、跨平台交易和退款等维度，推动学生认识到反洗钱不是单一分类模型，而是模型、权限、流程、审计和平台治理共同构成的系统工程。这一设计有效加强了学生的隐私保护、网络安全和负责任创新意识。

### 5. 学生具备了初步的软件工程和系统交付能力

项目形成了可运行的前后端平台原型：后端基于 Spring Boot、Spring Security、JWT、MyBatis 等技术，前端采用 Vue 和 Element UI，并通过 SQL 脚本组织用户、NFT、活动、交易和关系等业务数据。平台实现了风险监测、可疑用户管理、交易链条追踪以及 NFT、活动和用户信息维护等功能。

这说明学生的产出已经从实验代码扩展为包含数据库、接口、权限和页面的系统化成果。算法结果能够被转化为业务人员可以查看和处理的风险列表，用户风险能够继续关联到交易链条，平台安全评估也能够从单笔交易上升到治理维度，体现了较好的工程落地意识和产品表达能力。

### 6. 学生形成了较强的项目表达和协作能力

项目同时保留技术文档、商业计划书、精益画布和展示汇报材料，说明学生需要面对不同受众进行表达：对技术人员说明数据和算法，对业务人员说明风险监测价值，对评审人员说明创新性、可行性和社会意义。项目成果覆盖代码、数据、SQL、平台、文档和演示材料，具有明确的分工协作和阶段性交付特征。

从教学角度看，这种多成果形态有利于教师依据过程材料评价学生的真实贡献，也有利于学生形成需求分析、技术写作、口头答辩和团队协作能力，而不是只依赖最终演示的视觉效果。

### 7. 综合评价

总体来看，本项目已经形成较完整的综合实验教学案例，主要教学成效可以概括为：**以真实复杂问题为牵引，促进学生完成从数据理解、算法实验、隐私分析到平台实现的连续实践；以可运行代码和平台成果承载学习证据，提升实验教学的真实性、综合性和可评价性；以类别不平衡、数据异常和联邦安全边界等问题引导学生反思技术结论，增强数据伦理和工程责任意识。**

项目现有材料足以证明“教学内容具有综合性、技术路线具有实践性、学生产出具有工程性、成果表达具有完整性”。同时，原始材料没有提供具体班级人数、学生成绩前后测、问卷统计或推广班级等量化教学数据，因此本评价不虚构这些数字。若用于正式教学奖申报，建议将本节与学校教务系统中的课程实施记录、学生作品、评分表、课堂过程材料和学生反馈一并提交，以形成“项目证据 + 教学档案”的完整证明链。

## 十、持续改进计划

下一阶段可将竞赛原型升级为更适合教学的版本：补充固定依赖和一键启动脚本；将随机示例改为可解释、可重复的模拟多方数据；引入时间切分、类别不平衡和误报成本分析；补充安全聚合、差分隐私和模型审计实验；增加自动化测试、个人贡献记录和在线实验评价表。这样既保持项目的真实复杂度，又降低学生第一次接触跨模块工程时的进入门槛。
