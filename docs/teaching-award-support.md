# 实验教学成果支撑材料

## 一、成果名称

**面向真实复杂问题的“数据—算法—系统—治理”贯通式实验教学：基于联邦学习的 NFT 可疑交易监测与平台安全评估项目**

本项目以 NFT 交易反洗钱这一跨学科、强实践、重安全的真实问题为载体，将数据分析、机器学习、隐私计算、数据库、软件工程、Web 开发、区块链和创新创业教育组织为一条连续的实验教学链路。学生不是只提交一个模型或一组页面，而是经历“发现问题—分析需求—处理数据—训练模型—讨论隐私—开发平台—评价安全—展示成果”的完整工程实践。

## 二、教学改革要解决的问题

传统实验容易出现三个断点：

1. **知识断点**：Python、数据库、机器学习和 Web 开发分别授课，学生会做局部练习，却难以理解知识如何共同解决复杂问题；
2. **任务断点**：实验以验证语法和复现算法为主，缺少需求分析、数据质量、模型解释、接口设计和系统交付等真实约束；
3. **价值断点**：学生往往只关注准确率，忽略隐私保护、权限控制、审计追踪、数据授权和模型局限，难以形成负责任的技术观。

本项目以一个可持续扩展的业务场景串联上述环节，用平台化成果承接算法结果，使学生能够看到知识从课堂概念转化为工程能力和社会责任。

## 三、教学目标

### 1. 知识目标

- 理解交易型数据的字段、标签、缺失值、类别不平衡和时间关联等基本特征；
- 掌握 XGBoost 的基本原理、关键参数、训练流程和准确率/AUC 等评价方法；
- 理解联邦学习“数据留在本地、协作训练模型”的基本思想，辨析联邦学习不等于天然安全；
- 掌握关系数据库建模、REST 接口、前后端分离和权限控制在业务系统中的作用；
- 了解 NFT 交易链条、平台治理和反洗钱风险之间的关系。

### 2. 能力目标

- 能够从业务问题抽象出数据字段、标签、实体关系和评价指标；
- 能够独立完成数据清洗、特征处理、模型训练、参数搜索、可视化和结果解释；
- 能够将算法输出设计为可查询、可追踪、可审计的平台功能；
- 能够阅读和修改跨语言工程代码，完成 Python、Java、Vue、SQL 之间的协同；
- 能够通过实验记录、技术文档、演示和答辩清晰表达技术方案与边界。

### 3. 素养目标

- 建立隐私保护、最小权限、数据授权和安全审计意识；
- 形成以证据和实验结果支撑结论的科研与工程习惯；
- 理解高准确率不等于高可靠性，能够主动识别数据泄漏、样本偏差和过拟合风险；
- 培养团队协作、项目管理、产品思维和面向社会问题的责任意识。

## 四、教学内容组织

项目按照能力递进组织为八个实验单元，每个单元既有可独立评价的产出，又为下一单元提供输入。

| 单元 | 核心问题 | 主要知识点 | 学生产出 |
| --- | --- | --- | --- |
| 1. 场景与需求 | 什么是 NFT 交易风险，谁需要系统 | 需求分析、用户画像、风险场景 | 问题定义、业务流程图、指标初稿 |
| 2. 数据认知 | 数据能否直接用于建模 | CSV、字段分析、缺失值、标签检查 | 数据字典、清洗记录、探索性分析 |
| 3. 模型基线 | 如何识别可疑交易 | 分类建模、训练/测试划分、准确率与 AUC | 基线模型与实验报告 |
| 4. XGBoost 优化 | 如何提升模型效果并解释结果 | 梯度提升树、参数搜索、特征重要性、学习曲线 | 参数对比、可视化和结论 |
| 5. 联邦协作 | 数据不能集中时如何共同训练 | 联邦学习、参与方、聚合、隐私边界 | 联邦流程图、原型代码、风险分析 |
| 6. 数据库与接口 | 模型结果如何进入业务系统 | 实体关系、SQL、REST、分页和权限 | 表结构、接口清单、后端模块 |
| 7. 平台实现 | 如何让业务人员使用结果 | Vue、交互设计、风险列表、链条追踪 | 风险平台页面和操作演示 |
| 8. 综合评价 | 系统是否安全、可用、可解释 | 平台安全评估、审计、伦理、项目表达 | 安全评估报告、答辩材料、反思报告 |

## 五、实验教学实施方式

### 1. 项目驱动

教师不以零散 API 演示作为主线，而是先给出“多个 NFT 平台希望联合识别可疑交易，但不能直接交换原始数据”的任务情境。学生围绕任务自主拆解角色、数据、模型、接口和平台功能，教师在关键节点提供最小必要的知识支架。

### 2. 分层任务

- **基础层**：完成数据读取、清洗、训练和指标计算；
- **提高层**：完成参数搜索、特征解释、联邦训练流程设计和数据库接口；
- **拓展层**：完成安全聚合、差分隐私、规则引擎、时间切分、模型监控或新的前端可视化设计。

分层设计既保证基础薄弱学生能够完成闭环，也为能力较强学生保留研究和创新空间。

### 3. 教师指导与学生协作

教学过程采用“教师示范关键方法—学生小组分工实现—阶段评审—同伴互评—教师反馈—迭代提交”的方式。建议小组设置业务分析、数据建模、算法、后端、前端和安全评估等角色，并要求每名学生提交个人贡献记录，避免只评价最终演示效果。

### 4. 过程性评价

评价不以一次性准确率或页面截图为唯一依据，而是综合考查问题理解、数据处理、算法实验、工程实现、安全意识、文档表达和团队贡献。建议评价构成为：过程实验 40%，阶段评审 20%，综合平台与技术报告 30%，答辩和反思 10%；教师可根据课程性质调整权重。

## 六、评价量规（可直接使用）

| 维度 | 优秀表现 | 合格表现 | 待改进表现 |
| --- | --- | --- | --- |
| 问题建模 | 能将业务风险转成清晰的标签、实体、指标和流程 | 能说明任务和主要数据对象 | 只描述功能，缺少问题定义 |
| 数据实验 | 清洗有依据，划分合理，能解释偏差与局限 | 能完成基本清洗和训练 | 直接套用数据，缺少记录 |
| 模型方法 | 能比较参数、指标和特征解释，避免只报单一准确率 | 能完成模型训练和基本评价 | 结论与实验不对应 |
| 隐私安全 | 能说明联邦学习边界、攻击面、权限和审计要求 | 能描述数据不出域的基本思路 | 将联邦学习等同于绝对安全 |
| 系统实现 | 数据库、接口、前端和模型结果形成闭环 | 有可运行的主要页面或接口 | 仅有静态页面或孤立代码 |
| 工程表达 | 文档完整、版本清晰、演示可复现、分工有证据 | 有基本报告和演示 | 只有最终截图，无法复核 |

## 八、教学创新与特色

### 1. 从“算法实验”升级为“完整工程实验”

学生不止训练模型，而是将模型结果继续转化为用户筛查、交易链条追踪和平台安全评估，完成从数据到系统的闭环，强化知识迁移和工程交付能力。

### 2. 将隐私计算从概念变成约束条件

“平台不能共享原始数据”不是课后讨论题，而是贯穿数据、算法和系统设计的真实约束。学生必须在模型效果、数据可用性、隐私风险和部署成本之间进行权衡。

### 3. 将安全与伦理嵌入技术评价

平台同时考察身份认证、双因素认证、最小权限、交易透明性、链条追踪和审计等指标，引导学生认识到一个识别率很高的模型，如果缺少权限、解释和治理，同样不能直接用于真实业务。

### 4. 用可运行平台承接学习证据

通过 API、数据库和前端页面，学生的学习成果从“代码文件”变为可操作、可演示、可评审的系统，便于教师进行过程观察、阶段验收和成果归档。

## 十、持续改进计划

下一阶段可将竞赛原型升级为更适合教学的版本：补充固定依赖和一键启动脚本；将随机示例改为可解释、可重复的模拟多方数据；引入时间切分、类别不平衡和误报成本分析；补充安全聚合、差分隐私和模型审计实验；增加自动化测试、个人贡献记录和在线实验评价表。这样既保持项目的真实复杂度，又降低学生第一次接触跨模块工程时的进入门槛。
