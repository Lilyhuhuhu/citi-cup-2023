# 技术方法

> 详细的数据字段、样本统计、实验结果和结果边界见 [数据、方法与主要结果](data-method-results.md)。

## 1. 业务建模

项目把 NFT 反洗钱拆为三个相互衔接的问题：

- 交易级别：识别疑似异常交易；
- 用户级别：聚合风险记录并筛查高风险用户；
- 平台级别：从用户认证、令牌铸造、NFT 上市和交易等维度形成安全评估。

## 2. 数据与特征处理

原型读取 `transactions.csv` 和 `transactions_micro.csv`，去除交易 ID、类型、时间戳等标识字段，对缺失值进行填充，再划分训练集和测试集。项目材料中的数据来自竞赛阶段样例，后续应用应增加时间窗口、账户关系、交易频率、金额分布、跨平台行为和链路统计等特征。

两份数据分别包含 1,048,575 条和 10,333 条记录，正例比例约为 0.1268% 和 0.4936%，属于明显类别不平衡场景。数据字段和标签位置不一致，实验前必须核对字段语义，不能机械地将最后一列当作标签。

## 3. XGBoost 模型

代码使用 XGBoost 的梯度提升树处理多维、非线性交易特征，并通过 `GridSearchCV` 探索树数量和最大深度等参数。实验脚本同时输出准确率、ROC AUC、学习曲线和特征重要性，为模型解释和参数选择提供依据。

原型代表性设置包括 `max_depth=3`、`eta=0.1`、`subsample=0.7`、`colsample_bytree=0.7` 和 500 轮训练。由于正例极少，教学复现实验还应增加 Precision、Recall、F1、PR-AUC、混淆矩阵和阈值分析。

## 4. 联邦学习思路

FedBoost 的基本流程是：各 NFT 平台保留本地交易数据，在本地训练模型或模型更新，仅将可聚合的信息发送到协调方；协调方完成聚合后再下发联合模型。这样可以减少原始交易数据集中化带来的隐私风险，并利用多平台数据提升识别覆盖面。

需要特别说明：当前 `FedBoost.py` 是竞赛阶段的概念验证代码，依赖较旧的 PySyft/Torch 接口，且示例中使用了随机数据和简化聚合逻辑。它用于展示方法路径，不应直接作为生产级安全聚合实现。

## 5. 安全评估方法

平台安全评估围绕以下维度组织指标：身份认证与双因素认证、令牌合约与元数据、最小权限和缓存管理、交易透明性、公平性、版权收费、跨平台交易及退款机制。评估结果可以与模型告警结合，形成“交易监测 + 平台治理”的闭环。

## 6. 主要结果与边界

原始实验记录给出 IBM 数据集准确率 `0.9998617170922443`、micro 数据集准确率 `1.0`。由于记录未同时保留完整混淆矩阵、概率输出、固定划分和运行环境，结果应作为竞赛阶段原型记录，而不是生产性能承诺。详细分析和可复现实验改进见 `docs/data-method-results.md`。
